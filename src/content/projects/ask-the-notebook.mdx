Ask Astro is Astronomer's open-source assistant for questions about Apache Airflow. The part I recognize is not the chat box. It is the pipeline under the box. Airflow DAGs fetch documents, cut them into chunks, embed the chunks, and load a vector database. The assistant is supposed to answer from that index, with the sources attached.

That is a data pipeline pointed at a language model. Pipelines are the work I already know how to read.

## RAG, in plain language

Retrieval-augmented generation, RAG for short, means the model is not asked to answer from memory alone. Something searches a pile of documents first. The model writes from what came back, and the reply can name those documents. Lewis and colleagues wrote the pattern up at NeurIPS in 2020. The Ask Astro README points at that paper.

The search is the grounding. If the search is stale, or the chunk is the wrong size, the written answer is grounded on the wrong page. That is why the unglamorous half, the ingest, is the half an orchestrator is good at.

## What Ask Astro actually runs

The [repository](https://github.com/astronomer/ask-astro) describes three loops. I am paraphrasing the README, not a private deployment.

**Ingest.** A set of Airflow DAGs pulls a source, splits Markdown, reStructuredText, and Python with LangChain, embeds the chunks with an OpenAI model, and writes the vectors to Weaviate. The README's source list is the Airflow docs, Astronomer docs, the Astronomer blog, the Astronomer Registry, Airflow GitHub pull requests, OpenLineage, and a Stack Overflow dump. The bulk DAG `ask-astro-load-bulk` saves extracted documents as parquet the first time, so a later run can try a new chunk size or a new database without downloading everything again. Astronomer wrote this up as [operationalizing ingest](https://www.astronomer.io/blog/ask-astro-operationalizing-data-ingest-for-retrieval-augmented-generation-with-llms-part-3/).

**Question time.** This part is an API, not a DAG. The README's chain asks a model for two reworded prompts, embeds those plus the original, and pulls up to 100 documents for each from Weaviate. A Cohere reranker keeps 8. A smaller model drops the ones that are off topic. A larger model writes the answer. The README names `gpt-3.5-turbo` for the cheap steps and `gpt-4o` for the final answer.

**Feedback.** A person can mark an answer correct or incorrect. A model scores helpfulness, publicness, and whether it stayed on topic. When both say the pair is good, a DAG writes the question and answer back into Weaviate, so a later question can retrieve it. The [introduction](https://www.astronomer.io/blog/ask-astro-open-source-llm-application-apache-airflow/) is the short version. The 2023 post links a public app at `ask.astronomer.io`. That address now redirects to Astronomer's product docs, so I am treating the repository and the write-ups as the sources.

## Where Airflow sits, and where a model call sits

A [DAG](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/dags.html) is a directed acyclic graph of tasks. An edge means "wait until upstream has succeeded." In Ask Astro, Airflow's job is the ingest and the feedback. It does not invent the sentence. It delivers the records the sentence is grounded on. The scheduler, the retries, and the log are the same habits as any other pipeline.

There is a newer, different pattern. The provider [`apache-airflow-providers-common-ai`](https://airflow.apache.org/docs/apache-airflow-providers-common-ai/stable/index.html) can make the model call itself a task. `LLMOperator` and the `@task.llm` decorator send a prompt through an Airflow connection. The docs say the provider needs Airflow 2.11 or later, and some extras need Airflow 3. That is worth knowing. It is not what the Ask Astro ingest DAGs are doing. Those DAGs move documents. The model sits in the API at question time.

## What this page actually runs

The widget below is not Ask Astro. Nothing is embedded. No model is called. There is no network request and no API key.

What it keeps:

- A pipeline you can edit. Extract, chunk, clean, filter, score, and index are tasks you add, reorder, and remove. A bad order, such as chunking before anything is extracted, refuses to run and says why.
- Real step results. Each task reports what it did: how many documents, how many chunks, how many duplicates dropped, how many terms. Open a task for sample rows and the time the browser spent.
- A real search over whatever that run indexed. BM25 or a plain keyword count, your choice. The answer is copied out of the top chunks. Change the chunk size and the scores move. Run history keeps the last few indexes so the same question can be scored on each.

What it drops:

- Vectors, Weaviate, Cohere, and every model name in the README. The score task counts words and says so.
- Query rewriting. Ask Astro asks a model for two extra phrasings. This page searches the words you typed.
- Any claim that the ranking is semantic. "Arm" will not find "manipulator." If the words are not in a chunk, the page says it has nothing to quote.

<h2 id="how-i-built-it">How I built it</h2>

The page is this MDX file. The widget is a React island, `src/components/demos/AskNotebook.tsx`, loaded with `client:load`, the same pattern as the tabletop and the two-link arm. Astro sends that component's JavaScript to the browser and leaves these paragraphs as ordinary HTML.

The documents, the chunk windows, the dedupe, and both rankers live in `src/components/demos/notebook.ts`. The drawing file stays about the canvas. A title word can count extra, so a question that echoes a passage's name beats a longer passage that only mentions the words. A trailing "s" is ignored, so "vectors" matches "vector." That is the whole stemmer, and the file says so.

Dragging uses dnd-kit. That library is imported only by this island, so the rest of the site does not download it. The Add, Up, and Down buttons are the fallback when a drag is awkward, which includes a keyboard and a small screen.

There is no API key. The browser does the work. Colors use the site's CSS variables, so the light and dark themes both apply. If the browser asks for reduced motion, Run skips the timer and shows every task result at once. The durations on the tasks are still the real compute times.

`scripts/check-notebook.ts` re-runs the questions and a few pipelines without a browser. It checks that "What is Ask Astro?" quotes the Astronomer passage, that an unknown question is not quoted, that chunking before extract is refused, and that a shorter chunk window changes the retrieved text.

The Python file `airflow/dags/build_notebook_index.py` is the same idea as a real DAG: read the markdown, split it, count terms, write JSON. The site build does not call it, and Vercel does not deploy that folder. Run it with the standard library if you want to see the index on disk. If Airflow is installed, importing the file registers a DAG named `build_notebook_index`. The score task still does not call a model. A comment marks the line where an embedding call would go.

The courses on the [certifications](/learning/certifications) page, Agentic AI and Building and Evaluating Data Agents among them, are why retrieval is on my mind. The About page already lists Airflow-style orchestration (Meta Dataswarm). This demo is those two lines on one screen, at a size I can read.
