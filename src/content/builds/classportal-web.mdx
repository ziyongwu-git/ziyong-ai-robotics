ClassLista is a multi-school web app for studios and schools of any kind. The home page says "Every class confirmed before it starts." It runs classes, attendance, invoices, and payments. The Chinese name is 课堂通.

The live app is [classlista.com](https://classlista.com).

## How I built it

I shipped ClassLista in about three weeks in November 2026. I run it as a product lead with a small team of agents. The work moves through six stages. I set the direction. I approve anything that touches production, money, deletes, or auth, and I merge.

Grok is the coordinator. It is a Grok Bot agent for ClassLista. It keeps the backlog, writes the briefs, reviews plans, and launches the Cursor cloud coding agents. Claude drafts the living roadmap. The two of them coordinate directly, through a shared-docs channel in the repository. The channel has a protocol guide, an inbox for Grok and an inbox for Claude, a shared status board, an append-only decisions log, and handoff templates. AGENTS.md and CLAUDE.md tell every agent to read its inbox and the status board at the start of a session, and to update them at the end. Grok also keeps a local synced checkout and reads and writes the same files.

Claude flags a risk in Grok's inbox. Grok queues it and briefs a Cursor agent. The decision lands in the shared log.

Cursor cloud agents built the first version: the core app, languages, families, the in-app assistant, attendance, and the security lockdown. Several can work at once, so more than one pull request can land in the same hour. Claude Code, in the cloud, became the main feature builder and shipped most of the later features. Each builder takes one scoped change on its own branch and opens a small pull request.

GitHub Actions CI runs typecheck, tests, and the build on every pull request. ESLint, Prettier, and Dependabot run with it. I review, and I merge. Railway deploys the Docker image to classlista.com. Grok checks production and handles the domain, DNS, and email through Resend. Grok also audits what shipped and fixes drift, such as stale docs. Every two weeks Grok hands the story to the website assistant, another Grok Bot agent, which writes it into this page.

Under the middle stages sits the shared state: the repository, AGENTS.md, CLAUDE.md, the roadmap, the backlog, and the handoff docs. The rulebooks are for anyone changing this code, human or AI tool. Production checks and audits feed the backlog, so what ships comes back to the plan.

Other assistants triage email and watch AI news, so my attention stays on product. The in-app assistant, inside the product, defaults to Grok. OpenAI or Anthropic are optional. It is read-only, and it stays inside the asker's role. English, Chinese, and Spanish were in from early on.

Give each model the job it is best at. Grok coordinates and runs operations. Claude and the Cursor agents build. Keep the shared rulebooks, and keep a human approving what merges.

4. CI passed.

## School admins

Setup cards open a school one step at a time. The school uses its own colors and logo. Each school sets the sender name and the reply-to on its email, and each school has a join code. An admin can switch a teacher's self-serve powers on or off. Make-up classes stay off until the school opts in. The school lists how families pay. An admin can download all of a school's data as a zip, including money exports for an accountant.

## Teachers

Attendance is Present, Absent, or Excused. On the Today screen a teacher marks it in one tap, and can edit it for 30 days. A corrected class adjusts the invoice with a credit or a charge. Teachers have self-serve powers, and an admin can switch those powers on or off.

## Families

A family joins with a code. The join page shows where that family stands. A class email includes Coming and Can't make it. Each one is a single tap, with no sign-in. A family can say yes to the rest of the term. Make-up classes show up when the school has opted in. A family can tap "I've paid" and attach a screenshot of the payment. They can choose a weekly summary email, a monthly one, or none.

## Owner

The owner has a platform home, a page per school, a usage dashboard, and pages for emails, activity, the system, and people. Open as admin is a support mode, and it is time-limited. Suggest a feature sends that note to the website admin.

## Scheduling

A term has a roster. A class can meet at several times each week, and it can repeat until a date. This class and the following ones can be edited or cancelled. The app warns when the same teacher, the same room, or the same child would clash. Staff Planner groups the schedule by teacher, room, student, or family. Holidays can start from suggested days. A school can add its own days off, with conflict warnings and reminders. Each place has its own time zone, and class times use that place's clock. The class dates on an invoice follow that same clock. Invoice due dates follow the school's main place. Copy for WeChat is on a class and on a holiday. A class schedule can be copied for that class's WeChat group. That note has no children's names and no amounts. A session can be accepted or declined, and the answer shows on a calendar. On a phone, the calendar opens as a list of what is coming up.

## Money

Invoices show Paid, Unpaid, or Overdue, and staff record payments. A school lists how families pay: Zelle, Venmo, PayPal, a card link to the school's own Stripe, Square, or PayPal page, bank transfer, check, cash, WeChat Pay, Alipay, or a custom method. A family taps "I've paid" and can attach a screenshot of the payment. Staff can attach a screenshot or a receipt when they record a payment, and they confirm. The app keeps payment records and refund records. Copy for WeChat on an invoice is a private note of what that family owes. ClassLista does not move the money.

## Languages

The app is in English, Chinese, and Spanish. A test fails when a translation is missing. The public landing page has a language picker. Notices, dates, and amounts follow the reader's language. The design is kid-friendly, and the tooltips are accessible.

## The assistant

ClassLista has an in-app AI assistant. It is there for sales and for guidance. Grok is the default. OpenAI or Anthropic are optional.

How-to answers are grounded in the step-by-step help guides. "Take me there" highlights the field you asked about. Lookups are read-only, and they stay inside the role and the school of the person asking. There is a setup checklist, and a place to capture a lead.

Requests are rate-limited. Chats are kept for 30 days, and there is an admin page for them. If no API key is set, the assistant searches the help docs instead of calling a model.

## How it is put together

The front of it is Next.js 15, React 19, and TypeScript, styled with Tailwind v4. The type is Bricolage Grotesque and Figtree. On screen there is a floating tab bar, drawn status icons, an app icon, and a preview when a link is shared.

Data is Prisma 6 on SQLite, on a persistent volume. Sign-in is a custom session: bcrypt for passwords, hashed tokens for the session. Changes go through server actions checked with zod 4, and queries are scoped to the role and the school.

It runs on Railway, in Docker, on Node 22. Platform email sends through Resend, from its own mail domain. Tests run with Node's built-in test runner, via tsx. GitHub Actions runs CI. ESLint, Prettier, and Dependabot are part of the setup. There is a health page.
