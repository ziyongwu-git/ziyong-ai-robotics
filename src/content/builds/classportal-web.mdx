ClassLista is a multi-school web app for dance-school-style programs. It runs classes, attendance, invoices, and payments. The Chinese name is 课堂通.

The live app is [classlista.com](https://classlista.com).

## How I built it

I built and shipped ClassLista in about three weeks in November 2026. I work like a product lead running a small team of AI agents. Each agent has a defined role. I make the product calls, set the guardrails, and review what ships.

Grok is the product coordinator and the operator. It is a Grok Bot agent dedicated to ClassLista. It keeps the backlog, writes the briefs, and reviews plans. It launches the Cursor cloud coding agents, checks production, and handles operations such as the domain, DNS, and email setup.

Those Cursor agents built the first version: the core app, languages, families, the in-app assistant, attendance, and the first security lockdown. Several can work in parallel, so more than one pull request can land in the same hour. Claude, running Claude Code in the cloud, then became the main feature builder. It shipped most of the later features as small pull requests, and it drafted a living product roadmap.

There is no live chat between them. I am the relay and the decider. They coordinate through shared artifacts: the repository, a shared AGENTS.md rulebook, and the roadmap. The rulebook is written for anyone changing this code, human or AI tool: Claude Code, Cursor, or Grok.

Claude's roadmap flagged trust risks in the live demo login. Grok agreed, folded that into the backlog, and had a Cursor agent ship the lockdown first. Grok audits what Claude ships, checks production, and fixes drift such as stale docs. Operational news, such as email going live, comes back to Claude through me.

Every two weeks Grok hands off to the website assistant, another Grok Bot agent, which turns that handoff into this page. Other assistants handle email triage and AI news, so my attention stays on product decisions. English, Chinese, and Spanish were in from early on.

Give each model the job it is best at. Grok coordinates and runs operations. Claude and the Cursor agents build. Keep one shared rulebook, and keep a human deciding what merges.

## School admins

Setup cards open a school one step at a time. The school uses its own colors and logo. Each school sets the sender name and the reply-to on its email, and each school has a join code. An admin can switch a teacher's self-serve powers on or off. Make-up classes stay off until the school opts in. The school lists how families pay.

## Teachers

Attendance is Present, Absent, or Excused. On the Today screen a teacher marks it in one tap, and can edit it for 30 days. A corrected class adjusts the invoice with a credit or a charge. Teachers have self-serve powers, and an admin can switch those powers on or off.

## Families

A family joins with a code. The join page shows where that family stands. A class email includes Coming and Can't make it. Each one is a single tap, with no sign-in. A family can say yes to the rest of the term. Make-up classes show up when the school has opted in. A family can tap "I've paid".

## Owner

The owner has a platform home, a page per school, a usage dashboard, and pages for emails, activity, the system, and people. Open as admin is a support mode, and it is time-limited. Suggest a feature sends that note to the website admin.

## Scheduling

A term has a roster. A class can meet at several times each week, and it can repeat until a date. This class and the following ones can be edited or cancelled. The app warns when the same teacher, the same room, or the same child would clash. Staff Planner groups the schedule by teacher, room, student, or family. Holidays can start from suggested days. A school can add its own days off, with conflict warnings and reminders. Each place has its own time zone. A session can be accepted or declined, and the answer shows on a calendar. On a phone, the calendar opens as a list of what is coming up.

## Money

Invoices show Paid, Unpaid, or Overdue, and staff record payments. A school lists how families pay: Zelle, Venmo, PayPal, a card link to the school's own Stripe, Square, or PayPal page, bank transfer, check, cash, WeChat Pay, Alipay, or a custom method. A family taps "I've paid", and staff confirm. The app keeps payment records and refund records. ClassLista does not move the money.

## Languages

The app is in English, Chinese, and Spanish. A test fails when a translation is missing. The public landing page has a language picker. Notices, dates, and amounts follow the reader's language. The design is kid-friendly, and the tooltips are accessible.

## The assistant

ClassLista has an in-app AI assistant. It is there for sales and for guidance. Grok is the default. OpenAI or Anthropic are optional.

How-to answers are grounded in the step-by-step help guides. "Take me there" highlights the field you asked about. Lookups are read-only, and they stay inside the role and the school of the person asking. There is a setup checklist, and a place to capture a lead.

Requests are rate-limited. Chats are kept for 30 days, and there is an admin page for them. If no API key is set, the assistant searches the help docs instead of calling a model.

## How it is put together

The front of it is Next.js 15, React 19, and TypeScript, styled with Tailwind v4. The type is Bricolage Grotesque and Figtree. On screen there is a floating tab bar, drawn status icons, an app icon, and a preview when a link is shared.

Data is Prisma 6 on SQLite, on a persistent volume. Sign-in is a custom session: bcrypt for passwords, hashed tokens for the session. Changes go through server actions checked with zod 4, and queries are scoped to the role and the school.

It runs on Railway, in Docker, on Node 22. Platform email sends through Resend, from its own mail domain. Tests run with Node's built-in test runner, via tsx. GitHub Actions runs CI. ESLint, Prettier, and Dependabot are part of the setup. There is a health page.
